# quant-core final base spec (from the repo owner; runs last)

Role: lead architect finishing the base. NOT building more: audit what exists against the four earlier prompts (bootstrap, autonomy, decision layer, self-learning), consolidate into one architecture, cut scope to a general core plus ONE vertical, make repo contributor-ready.

Scope rule (overrides earlier prompts): **General interfaces, one implementation.** Core must be able to support any market family (order-book markets, event contracts, later others). Only one vertical implemented end-to-end until it has a live reconciled track record. Everything else = interface + ADR + roadmap entry. No half-built adapters, no speculative code. Half-built components for non-selected verticals: don't delete history; move to a `parked/` note in the roadmap and remove code from the build, with a PR explaining each removal.

Rules: plan in docs/plans/0005-base-complete.md first; one phase per PR; stop for approval; verify external APIs/tools against current official docs; never touch protected zones without human approval.

## Phase 1 — consolidated architecture (docs/ARCHITECTURE.md single source of truth, Mermaid per layer + overview)
Layers: 6 governance (risk limits★, kill switch, track record★, compliance★) · 5 control plane (swarm, autonomy loops, decision layer, knowledge loop, evals, backlog, weekly reports) · 4 learning (L0-L3, registry, graveyard, monitoring, demote-auto/promote-human) · 3 strategies · 2 market families (orderbook-family; event-family: binary/scalar contracts, settlement, resolution rules; each: schema, fill model, label defs, settlement, adapters) · 1 core (domain model, event bus, clock, OMS, risk engine, portfolio, replay/determinism, data catalog, telemetry).
Core contracts: Instrument (id, family, tick/price representation, contract size, expiry/settlement type), MarketFamily, VenueAdapter (market data, order entry, reconciliation, rate limits, drop copy), Strategy (events -> intents, never talks to venues), SignalSource (fast in-engine + slow), RiskCheck (pre/post-trade; per instrument, family, global), Learner (L0-L3 hooks).
Slow signals ADR-0021: offline forecasters publish signed, timestamped, versioned forecast records to a signal store; engine reads latest valid via SignalSource with staleness bound, max-influence bound (config/limits/, protected), signature verification; invalid/stale/unsigned = no signal; root rule 1 holds. Leakage rule: LLM/Jev forecasts not valid in historical backtests, forward shadow evaluation only; research CLAUDE.md + registry flag blocking them from historical validation.
Vertical (kalshi-events example): engine/crates/gateway/kalshi/ generated from official OpenAPI/AsyncAPI pinned + spec hash; demo env for all tests/paper; prod creds only after human approval; keys in secret manager; gateway/kalshi/CLAUDE.md quirks each verified against demo + official docs (community-reported quirks like bids-only book where yes-ask derives from best no-bid, positions lagging fills are unverified until tested). families/event/: contract model, settlement/resolution rules, binary-book fill model, labels (probability calibration vs resolved outcomes), resolution-source metadata. Strategies: disciplined MM with inventory + resolution-risk controls; forecast-driven taking using slow signals, forward-evaluated only. Risk: per-event max exposure, correlated-event grouping, max loss per resolution date, halt on resolution-source anomalies.
