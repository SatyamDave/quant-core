# Evidence-driven trading research loop (from the repo owner, 2026-09-27). This supersedes the earlier prompts where they conflict.

Goal: improve ability to discover, falsify, reproduce, and safely deploy genuine edges. Ambitious about research, strict about evidence. Challenge assumptions incl. this prompt. No flattery, no market-leadership promises, no mistaking architectural complexity for progress. Turn prior prompts into one executable process; preserve useful implementations and protections; complete the smallest meaningful research cycle before expanding.

## 1 Audit and scope
Read all earlier prompts (Bootstrap, Autonomy, Decision Layer, Self-Learning, Final Base, Team) and the actual repo (instructions, deps, tests, CI, datasets, experiment records, deployment config; never expose credentials). Inventory with evidence paths: Component | implemented and verified | partial | proposed only | contradictory | keep/fix/defer. List missing inputs. A summary is not the full prompt; README claim not an implementation; mock not an exchange integration. Identify venue, instruments, hypothesis, horizon, data, hardware, account permissions, budget, whether trading disabled; unknown -> reversible offline assumptions, explained. No inferred authorization to spend or trade. If no market selected, recommend one provisional research target from actual data availability, fees, liquidity, ops, constraints; Kalshi is a candidate, not approved; verify via official sources; continue with local baseline while external access blocked. Define HFT operationally (what signal decays, horizon, latency required, measured infra); measure local processing separately from network RTT and exchange acks; don't call ordinary API automation HFT.

## 2 Truthfulness
Material claims tagged VERIFIED / HYPOTHESIS / UNKNOWN / REFUTED with source, file, test, or artifact. Never invent APIs, numbers, citations, models, commands run, test passes, deploy status, profitability. "Not measured" valid. Vendor claims separate from our measurements. Primary sources opened, access date + version recorded. Status boundaries: proposed, implemented, executed, independently checked, promoted — never collapse to "done". Failed runs preserved and diagnosed; never substitute synthetic results or modify tests/labels/metrics/datasets to pass. Synthetic data tests mechanics only, labeled, never evidence of edge.

## 3 Small architecture
Three responsibilities in existing repo: Research (agents may help); Evaluation and promotion (reproducible measurement, protected eval inputs, artifact versioning, explicit advance decisions); Trading runtime (bounded inference, order state, inventory, deterministic risk, venue comms, reconciliation). No hosted LLM / browsing / agent coordination blocking the order path; small local model only after correctness + latency measurement. Research outputs enter via versioned validated artifacts with provenance, freshness limits, schema checks, bounded influence. Predefined runtime policy for expired signal / model failure / stale data; disabling new exposure and managing existing orders are separate actions; never assume kill switch cancels acked orders, pending requests, or positions. Share only needed primitives (ids, timestamps, prices/qty, order lifecycle, inventory, accounting, risk decisions, replay); venue specifics (ticks, settlement, fees, margin, order semantics, payout) in adapters. One implementation first; abstractions expand when a second real use case demands. No microservices or agent framework for appearance.

## 4 Technology earns adoption
Per milestone, bounded review of primary docs/releases/papers/reference code; at most three candidates addressing a measured bottleneck; record Candidate/version | problem | evidence | access/license | data exposure | cost | integration effort | baseline | adoption test | removal path. Capabilities (structured tool calls, checkpoints, retrieval with provenance, routing/abstention, task classifiers, parallel agents, distillation) each need their stated comparison (e.g. parallel agents vs one agent at equal budget; classifiers vs rules, logistic regression, tree). Pin versions; log resolved versions; quarantine unannounced provider changes. Keep existing framework unless replacement shows net benefit. Jev = candidate decision service; verify capabilities, availability, data policy, latency, versions; TypeSafe docs say Jev does not fine-tune/LoRA-adapt on customer data; if using Jev outputs to train our own classifier describe accurately (and check contract terms); validate on our labels. Prefer ordinary rules when adequate.

## 5 Bounded research loop (every cycle; may end in rejection or insufficient evidence; never manufacture a winner)
A Select one uncertainty: mechanism, why it exists, why competitors haven't eliminated it, falsifying observation; separate forecasting skill / execution quality / software reliability; rank by decision value vs cost; one primary experiment in first cycle.
B Register before measuring outcome: hypothesis, baseline, dataset + availability times, target + label horizon, split rules, candidate search budget, primary metric, minimum useful effect, evaluation method, failure criteria, compute limit, decision rule. Freeze config; later changes are new trials. Thresholds from task economics, not copied targets.
C Validate data: event time, publication time, first observed/available time, ingestion time, revisions, final label availability; only info available at simulated decision time; fit preprocessing/features/selection/calibration within training partitions; check missing, duplicates, sequence gaps, clock, selection effects, survivor bias. Event contracts: preserve settlement rule + version; related contracts on one event are not independent.
D Baseline: simple rule, no-trade, market-implied forecast, or conventional model; same information, exposure constraints, costs; explain fairness. First useful output may be reliable data capture + baseline report.
E Limited candidate comparison: one mechanism at a time with ablation; store code revision, dependency lock, dataset fingerprint, split manifest, seed, model/prompt version, feature config, runtime, cost, output, failures. Hosted model calls not bit-reproducible: save requests/responses within data policy; replay vs new call separated.
F Evaluate without leakage: chronological, purge overlapping labels, justified gap; tuning separate from final held-out; once eval informed changes it's no longer untouched; forward data for later claims. Account for full search. Stats fit sample size + dependence; report uncertainty and effective independent observations; correlated trades aren't independent. DSR where assumptions fit; no statistic repairs leakage. Retrospective LLM forecasts exploratory only; prospective timestamped predictions primary.
G Execution economics: after fees, spread, latency, slippage, partial fills, queue uncertainty, impact, adverse selection, capital constraints. Touching a limit price doesn't guarantee fill. Candles can't establish queue-sensitive execution. Downgrade claims data can't support. Trading economics separate from research/operating costs; show both.
H Verify independently: re-run from saved manifest in clean env; verify accounting, sample construction, baseline fairness, artifacts; separate review pass + protected deterministic checks; another model agreeing isn't financial evidence; candidate can't rewrite evaluator or read held-out labels.
I Decide + preserve: PROMOTE TO NEXT STAGE / REJECT / INSUFFICIENT EVIDENCE with reason; negative result in ledger with revisit conditions; concrete next action (stop, repair data, collect labels, test different mechanism, begin shadow). Don't keep searching the same data until something passes.

## 6 Learning defined
Separate: research memory (findings/rejections with sources, scope, date, recheck conditions); predictive learning (versioned features/classifiers/calibration on legitimate labels); agent improvement (tools/prompts/routing backed by task evals); execution improvement (measured fills, costs, latency, reconciliation). Memory notes don't train weights; self-critique isn't ground truth; more iterations ≠ improvement. Champion-challenger; retraining yields candidate, never authority to raise risk or deploy; drift triggers investigation + predefined policy; delayed labels + missing counterfactuals; selection bias if only executed trades labeled; no real-money exploration for data. Offline updates + shadow first; defer RL/online policy adaptation.

## 7 Agents as software
Small versioned eval suite from first workflow's actual failures (unsupported citations, inaccessible sources, insufficient evidence, malformed outputs, conflicting observations, time leakage, prompt injection, budget exhaustion, interrupted runs, safe recovery). Code-verified where possible. Track task success, unsupported claims, correct abstention, tool errors, unauthorized actions, recovery, time, cost per verified outcome. Trading model quality separate (discrimination, calibration, proper scoring rules, decision utility after costs, regime failure). Explicit tool schemas, scoped permissions, bounded retries, durable job ids, resumable state, dedupable retries; ambiguous order responses reconciled before retry. One agent + separate verification pass first; parallel agents only for separable work with measured benefit; no debating swarm; agents never grant each other permissions/budgets.

## 8 Both contributors, same process
Concise shared CLAUDE.md (purpose, boundaries, actual commands, links to procedures). docs/NOW.md short: current milestone, next task, blockers, deferred work. Reuse existing equivalents, no duplicate docs. Session start: inspect instructions + latest relevant handoff. Checkpoint: update what changed, what was actually verified, next runnable action. Branches/worktrees for simultaneous edits. Shared config via git; personal memory isn't source of truth. Do NOT claim project Markdown overrides every personal instruction or enforces security; verify installed config + official docs; hooks help only within covered paths + protecting permissions; risk constraints in runtime checks and permission boundaries; branch/deploy protections outside agent's unilateral reach. Report configured, tested, still-unenforced controls separately. Maintainer review for risk, capital, credentials, deployment, evaluation-integrity; concrete diffs before approval requests; no new approval for ordinary authorized local work; don't claim two-maintainer approval is technically enforced until platform reviewer/bypass behavior verified. Every PR: problem, change, evidence, limitations, rollback/removal path; may record a rigorous negative finding. Replace "every metric beats all-time best" with hard correctness/risk invariants + statistically justified performance tolerances under comparable conditions; no test counts, raw coverage, or lucky bench peaks as progress proxies; no bot silently rewriting eval thresholds or blessing results it optimized.

## 9 Proprietary value
Legally usable high-quality observations, point-in-time datasets, trustworthy labels, accumulated experiments, validated features, measured execution knowledge. Public models/frameworks are inputs, not edge. Credentials out of git. Classify what may go to external providers; apply before tool calls; private repo doesn't stop an assistant transmitting source. Encryption at rest doesn't protect plaintext after decryption; restricted artifacts/keys in access-controlled stores, hashes in repo; no encryption machinery without threat model + recovery plan.

## 10 First cycle deliverables, in order
1 Short audit: reality, missing evidence, contradictions, single selected bottleneck.
2 Compact consolidated project instruction set + current milestone.
3 One registered experiment + reproducible baseline + manifest.
4 Executable check for the most consequential failure the audit exposes.
5 One measured result or honest blocked-run report, artifacts, exact next action.
6 Three-PR-max next-step plan tied to this research objective.
Near-empty repo: one command running a deterministic local fixture through data validation, baseline, accounting, report, no prod credentials, stated as plumbing only. Mature repo: real bounded baseline experiment. Budget: none configured -> local/dry-run, paid external calls disabled; budgets cover calls, retries, subagents, compute; terminate cleanly. Stages: offline research -> forward shadow -> sandbox integration -> explicitly authorized limited live -> reviewed scaling. Not authorized: live trading, new capital, paid services, deployment.
Conclude with: verified; unknown; attractive claims rejected; what the first cycle taught; next runnable command; plain language for the operator.
