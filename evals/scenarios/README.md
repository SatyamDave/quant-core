# evals/scenarios

Frozen worldlines for the Tier 2 agent eval (`scripts/eval/live_agent.py`, gated, run on merge to
main / nightly, never on every PR — see `evals/README.md`). A worldline is a fixed, pre-recorded
market-data slice the agent decides against: same input every run, so a prompt/tool/model change
can be compared to the champion on identical scenarios instead of live noise. Pattern per
`llm-trading-eval-research.md` §5 (FORESIGHT-9, arXiv:2608.29372): several small frozen scenarios,
not one long backtest window, because agent rankings vary across worldlines and a single window
hides that.

## Format

Each `worldline-NN.csv` is the record format documented in
`engine/crates/gateway/src/record.rs` (also `tests/replay/README.md`):

```text
# comment; blank lines are skipped
S,<instrument>,<seq>,<ts_exchange>,<ts_local>,<bids>,<asks>   snapshot; sides are price@qty;..., best first
D,<instrument>,<seq>,<B|S>,<price>,<qty>,<ts_exchange>,<ts_local>   book delta; qty 0 removes the level
T,<instrument>,<B|S>,<price>,<qty>,<ts_exchange>,<ts_local>         trade; side is the aggressor
```

Prices and quantities are fixed-point decimals; timestamps are nanoseconds. Every worldline opens
with a snapshot record so a consumer's book starts `Synced`, then a contiguous run of delta/trade
records — no lookahead is possible because records are only ever read in order, one at a time,
the same constraint `qc-replay` enforces on `tests/replay/sample_day.csv`.

## Provenance

All four are **synthetic** — never real market data — and each file's header comment says so.
`worldline-01` through `worldline-03` are sliced from `tests/replay/sample_day.csv` (itself
generated by `tests/replay/generate_sample_day.py`) and give their source sequence range.
`worldline-04-shock` is hand-constructed instead (see below) rather than sliced, because
`sample_day.csv` stays in a narrow band throughout and contains no shock to slice out. They exist
so `scripts/eval/live_agent.py` has a small, stable set of decision opportunities to run the agent
against, next to the free baselines computed on the same scenario (issue #37); they are not a
claim about any market.

| File | Source range | Note |
|---|---|---|
| `worldline-01.csv` | seq 1001-2438 | continuous from the snapshot, no gap |
| `worldline-02.csv` | seq 2439-3855 | opens on a sequence gap (seq 1000 to 2439): a resync a consumer must handle, not a fixture bug |
| `worldline-03.csv` | seq 3856-5260 | closing window, includes one trade record |
| `worldline-04-shock.csv` | hand-constructed, not sliced | **adversarial**: a quiet ~50-record opening, a 10-step ~5% price-shock gap (both sides of the book stepped down together, spread held at one tick), then a ~50-record quiet recovery — issue #37's "at least one deliberately hard case" |

## `from_ledger/` (issue #52)

A second, sibling source of scenarios: `scripts/eval/scenarios_from_ledger.py` generates
`from_ledger/*.csv` from real decision-ledger entries whose outcome is now known (a blocked
trade, a confident loss, or a declined trade that would have made money), each paired with a
`.provenance.json` sidecar (source ledger hash, entry index, selection reason, recorded outcome).
Unlike the four worldlines above, these are single-snapshot recordings — faithful to the source
entry's own recorded top-of-book, not to its recorded classifier `signal` (order-book/feature
history cannot be honestly reconstructed after the fact; see that script's docstring). Labelled
`synthetic` or `real` per the source ledger entry's mode. `scripts/eval/promote.py`'s frozen
suite includes this directory by default; `scripts/eval/live_agent.py`'s paid Tier 2 set does
not (a human reviews generated scenarios first).

## How a consumer should use these

A worldline is disclosed only in-world time order: a consumer reads records one at a time and
never peeks ahead in the file to decide the current one. This is what the bridge (`qc-bridge`,
`agentic/bridge`) and the fake/live TS agent service (`agent/`, `agentic/agent-service`) are
expected to do once those lanes land; nothing in this repo consumes these files yet. Regenerating
the underlying `sample_day.csv` (new seed, more events) changes these three files too — treat that
as a new set of worldlines, not an edit to the existing ones, and keep the three source ranges
documented above in sync.
